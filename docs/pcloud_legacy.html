pCloud Backup Tools (Legacy)

⚠️ Legacy 1:1 / flat manifest pipeline. Produktion pi-nas nutzt Pool-Modus (wrapper_pcloud_pool_sync_1to1.sh, pcloud_push_json_pool_manifest_to_pcloud.py, pool_verify_backup.py Integrity-Gate). Siehe Overview → pCloud Pool und POOL_INTEGRITY.md.

Detailed documentation for the pCloud 1:1 backup pipeline with EntropyWatcher safety-gate.

Production setup (home NAS) Python 3.11+ RTB + pCloud

1. Concept

The pCloud tools implement a 1:1 snapshot backup pipeline. Local RTB snapshots are turned into JSON manifests and uploaded to pCloud with SHA256-based deduplication and post-upload integrity checks.

Lokales Verzeichnis → Manifest (JSON) → pCloud Upload /srv/nas/User1/ manifest.json pCloud:/backups/ ├── Dokumente/ └── SHA-256 Hashes └── 1:1 Snapshot ├── Fotos/ └── Metadaten └── ...

2. Components

2.1 pcloud_json_manifest.py

Scans a snapshot directory and creates a JSON manifest with file metadata and SHA256 hashes.

python pcloud_json_manifest.py \
  --source /srv/nas/User1 \
  --output manifest_$(date +%Y%m%d_%H%M%S).json \
  --exclude ".git,node_modules,*.tmp"
{
  "created": "2025-11-23T15:30:00Z",
  "source": "/srv/nas/User1",
  "files": [
    {
      "path": "Dokumente/invoice.pdf",
      "size": 245678,
      "mtime": "2025-11-20T10:15:00Z",
      "sha256": "abc123...def456"
    }
  ]
}

2.2 pcloud_push_json_manifest_to_pcloud.py

Reads a manifest and uploads the referenced files to pCloud with integrity validation.

python pcloud_push_json_manifest_to_pcloud.py \
  --manifest manifest_20251123_153000.json \
  --pcloud-folder /backups/nas-user1 \
  --auth-token "YOUR_PCLOUD_TOKEN"

2.3 pcloud_quick_delta.py

Fast delta detection for uploaded snapshots. Compares the live state on pCloud (via listfolder) with the local content_index.json to detect missing files, unauthorized changes, or corruption.

python pcloud_quick_delta.py \
  --dest-root /Backup/rtb_1to1 \
  --snapshot 2026-04-10-075334 \
  --env-file .env \
  --json-out /tmp/delta_report.json

2.4 pcloud_repair_index.py

Repairs the local content_index.json when missing files are detected. Removes holders and anchor_path references for files that don't exist on pCloud anymore.

python pcloud_repair_index.py \
  --dest-root /Backup/rtb_1to1 \
  --env-file .env \
  --dry-run  # Preview changes first
  
# Apply repairs
python pcloud_repair_index.py \
  --dest-root /Backup/rtb_1to1 \
  --env-file .env

2.5 pcloud_integrity_check.py

Verifies that already uploaded data still matches the hashes from a manifest.

python pcloud_integrity_check.py \
  --manifest manifest_20251123_153000.json \
  --pcloud-folder /backups/nas-user1 \
  --auth-token "YOUR_PCLOUD_TOKEN"

2.6 pcloud_restore.py

Restores pCloud snapshots either as a classic flat tree or into an object-store layout with a shared _objects directory and hardlinked snapshots.

2.7 wrapper_pcloud_sync_1to1.sh

Orchestrates safety-gate check, manifest creation, upload and post-upload verification.

#!/bin/bash
set -e

SAFETY_GATE="/opt/apps/entropywatcher/main/safety_gate.sh"
SOURCE="/srv/nas/User1"
MANIFEST="/tmp/manifest_$(date +%Y%m%d_%H%M%S).json"
PCLOUD_FOLDER="/backups/nas-user1"

# 1. Safety gate
if ! "$SAFETY_GATE"; then
    echo "❌ Backup aborted - EntropyWatcher detected threats"
    exit 1
fi

# 2. Manifest
python3 /opt/pcloud/pcloud_json_manifest.py \
  --source "$SOURCE" \
  --output "$MANIFEST"

# 3. Upload
python3 /opt/pcloud/pcloud_push_json_manifest_to_pcloud.py \
  --manifest "$MANIFEST" \
  --pcloud-folder "$PCLOUD_FOLDER"

# 4. Post-Upload Verification (NEW!)
python3 /opt/pcloud/pcloud_quick_delta.py \
  --dest-root "$PCLOUD_FOLDER" \
  --snapshot "$(basename $SOURCE)" \
  --json-out "/tmp/delta_report.json"

# 5. Cleanup
rm "$MANIFEST"
echo "✅ Backup completed successfully"

3. System Architecture

This section summarizes how RTB snapshots, manifests, safety-gate and pCloud upload work together.

1. DATA SOURCE
   └─ /srv/nas/User1, /srv/nas/User2, /srv/nas/User3

2. SNAPSHOT CREATION (RTB)
   └─ /mnt/backup/rtb_nas/2025-11-24-120000/ (hardlinks + new files)
      /mnt/backup/rtb_nas/latest → 2025-11-24-120000

3. MANIFEST GENERATION
   └─ pcloud_json_manifest.py
      ├─ Scan snapshot directory tree
      ├─ Calculate SHA256 for each file
      └─ Output: /tmp/manifest.json

4. SAFETY GATE CHECK (EntropyWatcher)
   └─ safety_gate.sh
      ├─ Check entropy scans
      ├─ Check ClamAV findings
      ├─ Check scan age
      └─ Exit: 0=safe, 1/2=block

5. INTELLIGENT UPLOAD
   └─ pcloud_push_json_manifest_to_pcloud.py
      ├─ Read manifest items
      ├─ Check content_index.json on pCloud
      ├─ For each file: reuse or upload
      └─ Update content_index.json

6. POST-UPLOAD VERIFICATION (NEW!)
   └─ pcloud_quick_delta.py
      ├─ Compare live state vs. content_index.json
      ├─ Detect missing files
      ├─ Detect unauthorized changes
      └─ Report: JSON + console output

7. INDEX REPAIR (if needed)
   └─ pcloud_repair_index.py
      ├─ Remove holders for missing files
      ├─ Clear anchor_path if anchor missing
      └─ Save repaired index locally

8. RE-UPLOAD MISSING FILES
   └─ pcloud_push_json_manifest_to_pcloud.py (again)
      ├─ Resume-aware: skips valid files
      ├─ Uploads only missing files
      └─ Updates markers (.upload_complete)

9. pCLOUD STORAGE
   └─ /Backup/rtb_1to1/
      ├─ _snapshots/
      │  ├─ 2026-04-10-075334/
      │  │  ├─ .upload_started
      │  │  ├─ .upload_complete
      │  │  └─ snapshot files...
      │  └─ _index/content_index.json
      └─ future snapshots

4. Delta-Check & Repair Workflow

When interrupted uploads or file deletions cause missing files, use this workflow to detect and repair them without re-uploading the entire snapshot.

4.1 Scenario: Interrupted Upload

Upload was stopped at 15% progress. Resume mechanism should skip already uploaded files, but some are missing on pCloud.

4.2 Step-by-Step Recovery

# Step 1: Detect missing files
python pcloud_quick_delta.py \
  --dest-root /Backup/rtb_1to1 \
  --snapshot 2026-04-10-075334 \
  --env-file .env \
  --json-out /tmp/delta.json

# Output shows:
# Missing Anchors: 197

# Step 2: Repair local index
python pcloud_repair_index.py \
  --dest-root /Backup/rtb_1to1 \
  --env-file .env

# Output:
# Holders removed: 197
# Nodes with anchor_path=None: 197

# Step 3: Re-upload missing files
python pcloud_push_json_manifest_to_pcloud.py \
  --manifest /srv/pcloud-temp/manifest_2026-04-10-075334.json \
  --dest-root /Backup/rtb_1to1 \
  --snapshot-mode 1to1 \
  --env-file .env

# Output:
# uploaded=197 resumed=19,611 stubs=0

# Step 4: Final verification
python pcloud_quick_delta.py \
  --dest-root /Backup/rtb_1to1 \
  --snapshot 2026-04-10-075334 \
  --env-file .env

# Output:
# Missing Anchors: 0  ← SUCCESS!

5. Safety-Gate Integration

The backup pipeline relies on EntropyWatcher's safety-gate to block backups during ransomware or AV incidents.

Exit  Status  STRICT=0 behavior         STRICT=1 behavior
0     GREEN   backup runs               backup runs
1     YELLOW  backup runs with warning  backup blocked
2     RED     backup blocked            backup blocked

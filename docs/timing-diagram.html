🔀 Alternativ: Fehlerszenarien

Scenario 1: Safety-Gate RED

02:00:02 – Ransomware erkannt (flagged>0)

→ Exit 2 (RED) – ABORT!

→ RTB & pCloud überspringen

→ Lock released, Alert Admin

Scenario 2: Keine Änderungen

02:00:05 – DRY-RUN: Keine Matches (kein <>ch*)

→ RTB überspringen (NO_CHANGE_EXIT0=1)

→ Lock released (Exit 0 – graceful)

Scenario 3: Lock busy

02:00:01 – Kann Lock nicht in 2h akquirieren

→ EXIT 0 (skip) – verhindert Deadlock

⚠️ Kritische Punkte

1. Shared Lock – Selbes Lockfile für RTB & pCloud verhindert Parallelität

2. Zwei Gating-Ebenen – Safety-Gate + DRY-RUN = doppelte Absicherung

3. Automatische Verkettung – pCloud startet sofort nach RTB, Lock NOCH gehalten

4. Graceful Timeouts – Lock Timeout 2h, kein Hard-Abort, immer LOCKFILE released

5. DB-Konsistenz – Alle Events werden geloggt (MariaDB) für Audit Trail
